## 1. エグゼクティブサマリー

### 1.1 現状評価の概要

本レポートは、Azure CAF（Cloud Adoption Framework）の戦略フェーズに基づき、
組織のクラウド導入準備状況を多角的に評価したものです。
戦略・ガバナンス・プラットフォーム・運用・セキュリティの 5 領域にわたって
現状を診断し、クラウド移行に向けたロードマップの土台を提供します。

現時点において、組織は **クラウド移行の初期段階**にあります。
オンプレミス中心のインフラ運用から脱却し、ハイブリッドクラウドを経由して
Azure パブリッククラウドへ段階的に移行する方向性が戦略的に最適と判断されます。

主要な評価所見は以下のとおりです：

- **強み**: 経営層のクラウド移行への意欲は高く、予算確保の意思決定が進みやすい環境にある
- **弱み**: クラウド専門スキルを持つ人材が不足しており、FinOps・DevOps の文化的変革が未着手
- **機会**: データセンター設備の更改時期が迫っており、移行のビジネスケースを構築しやすいタイミング
- **脅威**: クラウドセキュリティ・コンプライアンス対応の遅れが事業リスクになり得る

### 1.2 クラウド導入の推進要因

| 推進要因カテゴリ | 具体的要因 | 優先度 |
|---|---|---|
| **マイグレーショントリガー** | データセンター設備更改（3 年以内）、ハードウェア保守切れ | 最高 |
| **マイグレーショントリガー** | IT 運用コストの増大（前年比 12% 増）、人材確保困難 | 高 |
| **イノベーショントリガー** | デジタルサービスの迅速な市場投入（TTM 短縮）ニーズ | 高 |
| **イノベーショントリガー** | データ分析・AI/ML 活用による競争優位性の確立 | 中 |
| **重要なビジネスイベント** | 個人情報保護法改正への対応強化、ISMAP 認定要件 | 高 |
| **重要なビジネスイベント** | M&A 後の IT 統合・標準化の必要性 | 中 |

|---|---|---|

## 2. 戦略的評価（@cloud-strategy 視点）

### 2.1 ビジネス目標とクラウド導入の整合性

#### 組織の戦略目標とクラウドの対応関係

| 組織の戦略目標 | クラウドによる実現手段 | 整合度 |
|---|---|---|
| 2 年以内に ITコスト 30% 削減 | Azure Reserved Instances、Azure Hybrid Benefit、PaaS 移行による運用コスト削減 | ◎ 高 |
| 新製品・サービスの市場投入期間を 40% 短縮 | Azure DevOps、GitHub Actions による CI/CD 自動化、コンテナ化 | ◎ 高 |
| グローバル展開（アジア太平洋地域） | Azure の東日本・西日本・東南アジアリージョン活用 | ○ 中〜高 |
| データ活用による顧客体験向上 | Azure Synapse Analytics、Azure Machine Learning の活用 | ○ 中 |
| セキュリティ・コンプライアンス強化 | Microsoft Defender for Cloud、Azure Policy、ISMAP 対応 | ◎ 高 |

#### 整合性評価

経営層が掲げる 5 つの戦略目標のうち、**4 つは Azure クラウドの機能と高い整合性**を持ちます。
特に「コスト削減」と「時間市場投入の短縮」は、クラウド移行の最も直接的な便益であり、
3〜12 ヶ月以内に定量的な成果として示すことが可能です。

データ活用・AI/ML については、現状のデータガバナンスが未成熟であり、
クラウド移行と並行したデータ戦略の策定が前提条件となります。

### 2.2 投資対効果（ROI）の初期試算

#### TCO 比較分析（5 年間）

以下は Azure Migrate TCO Calculator の推計値に基づく概算です：

| コスト項目 | オンプレミス（5年合計） | Azure クラウド（5年合計） | 削減額 | 削減率 |
|---|---|---|---|---|
| ハードウェア（サーバー・ストレージ） | ¥30,000万 | ¥0（CapEx 排除） | ¥30,000万 | 100% |
| ソフトウェアライセンス | ¥12,000万 | ¥7,200万（Azure Hybrid Benefit 適用） | ¥4,800万 | 40% |
| データセンター運用費（電気・冷却・スペース） | ¥8,000万 | ¥0 | ¥8,000万 | 100% |
| 人件費（インフラ運用・保守） | ¥25,000万 | ¥15,000万（自動化・アウトソース削減） | ¥10,000万 | 40% |
| ネットワーク・通信費 | ¥5,000万 | ¥3,500万 | ¥1,500万 | 30% |
| **合計 TCO** | **¥56,500万** | **¥36,700万** | **¥19,800万** | **35%** |

> **注意（重要）**: ハードウェア廃止・人件費削減はいずれも**移行完了後（Year2〜）**に実現するものです。
> Year1 は移行コンサルティング・トレーニング・並行稼働コストが発生するため、
> **投資フェーズ**として位置づけてください。

#### ROI 計算（現実的シナリオ）

```
クラウド移行の ROI 試算（5 年間・保守的試算）
【前提条件】
- 対象: 物理50台 / VM 280台（全体）
- 人件費単価: ¥36M/人年
- RI 割引率: 35%（3年 Reserved Instance）
- 並行稼働コスト（Year1）: ¥50M（オンプレ+Azure二重費用）を計上

コスト削減額（5年累計）:  ¥19,800万
収益向上額（5年推計）:    ¥8,000万  ※TTM 短縮による新規サービス収益
リスク回避額（5年推計）:  ¥3,000万  ※セキュリティ事故・規制違反ペナルティ回避
─────────────────────────────────────────────
総便益:                   ¥30,800万

移行総コスト:             ¥17,000万 ※初期投資¥12,000万＋Year1 並行稼働¥5,000万

ROI = (30,800 - 17,000) / 17,000 × 100 = 約 81%
投資回収期間（Payback Period）≈ 18〜24 ヶ月
```

> **注意**: 本試算は概算であり、実際のコストは組織固有の構成・契約条件によって変動します。
> 詳細は Azure Migrate TCO Calculator（https://azure.microsoft.com/ja-jp/pricing/tco/calculator/）
> を使用して精緻化することを推奨します。全文書で統一している財務前提は本セクション記載の通りです。

### 2.3 競合優位性分析

#### クラウド移行による競争優位性

**1. スピードの優位性（俊敏性）**
- 現状のインフラプロビジョニング期間: 平均 4〜8 週間
- Azure 移行後の目標: 数分〜数時間（Infrastructure as Code 活用）
- 競合他社比較: 業界大手の 70% 以上が既にクラウドネイティブ環境に移行済み

**2. イノベーション能力の優位性**
- Azure AI Services（Azure OpenAI Service、Cognitive Services）への即座のアクセス
- 大規模言語モデル（LLM）を活用した顧客対応自動化・業務効率化
- 業界特化型ソリューション（Industry Cloud）の活用可能性

**3. グローバルスケールの優位性**
- 60 以上の Azure リージョンによる世界展開の即時実現
- エッジコンピューティング（Azure Edge Zone）によるレイテンシ最小化

**4. セキュリティ・信頼性の優位性**
- Microsoft のセキュリティ投資（年間 $4 billion 超）による最新の脅威防御
- ISMAP 登録済みサービスの活用による政府調達対応

#### 競合ギャップ分析

| 競争要因 | 現状の自組織 | 競合他社平均 | Azure 移行後の目標 | ギャップ解消時期 |
|---|---|---|---|---|
| デプロイ頻度 | 月次 | 週次〜日次 | 日次〜時間単位 | 12 ヶ月以内 |
| システム可用性 | 99.5% | 99.9% | 99.95% | 18 ヶ月以内 |
| セキュリティインシデント対応時間 | 72 時間 | 24 時間 | 4 時間以内 | 12 ヶ月以内 |
| 新機能市場投入期間（TTM） | 6 ヶ月 | 3 ヶ月 | 6 週間 | 18 ヶ月以内 |

### 2.4 ワークロード優先順位付け（5R フレームワーク）

#### 5R 分類の定義と戦略的意義

| 戦略 | 定義 | 主なメリット | 適用条件 |
|---|---|---|---|
| **Rehost（リホスト）** | 変更なしでクラウドに移行（Lift & Shift） | 最速・低リスク、初期コスト削減 | 標準化されたワークロード、依存関係が少ない |
| **Refactor（リファクタ）** | 最小限の変更で PaaS を活用 | 運用自動化、スケーラビリティ向上 | コードの軽微な修正が許容できる |
| **Rearchitect（リアーキテクト）** | クラウドネイティブ設計に再設計 | 高い俊敏性、クラウド最適化 | 複雑なアプリケーション、高成長が見込まれる |
| **Rebuild（リビルド）** | クラウドネイティブで再構築 | 最大の革新性 | レガシー性が高く改修より再構築が効率的 |
| **Replace（リプレイス）** | SaaS ソリューションへ置換 | 運用負荷ゼロ、常に最新 | 汎用業務システム（ERP、CRM 等） |

## 3. ガバナンス評価（@cloud-governance 視点）

### 3.1 現行の IT ガバナンス成熟度

#### 成熟度評価（CMMI レベル準拠）

| ガバナンス領域 | 現状レベル | 説明 | 目標レベル |
|---|---|---|---|
| ポリシー管理 | Level 2（管理済み） | 基本的な IT ポリシーは存在するが、クラウド対応が未整備 | Level 4（定量的管理） |
| コスト管理 | Level 1（初期） | 予算管理はあるが、リソース単位のコスト配賦が困難 | Level 3（定義済み） |
| 変更管理 | Level 2（管理済み） | ITSM ツールで変更管理を実施しているが、自動化は未整備 | Level 4（定量的管理） |
| リスク管理 | Level 2（管理済み） | リスク台帳は存在するが、クラウドリスクが考慮されていない | Level 3（定義済み） |
| コンプライアンス管理 | Level 2（管理済み） | 手動監査中心で自動化による継続的コンプライアンスが未実施 | Level 4（定量的管理） |
| 資産管理 | Level 1（初期） | IT 資産台帳が最新でなく、シャドー IT が発生している | Level 3（定義済み） |

**総合ガバナンス成熟度**: Level 2（管理済み段階） → 目標: Level 3〜4

### 3.2 コンプライアンス要件

#### 対象規制と現状ギャップ

| 規制・基準 | 適用対象 | 現状の対応状況 | ギャップ概要 | 対応優先度 |
|---|---|---|---|---|
| **個人情報保護法（PIPA）改正** | 全社 | 部分対応 | クラウド上での個人データの処理・越境移転の管理が不十分 | 最高（法的必須） |
| **ISMAP（政府情報システムセキュリティ評価）** | 政府向けサービス提供時 | 未着手 | Azure ISMAP 登録サービスの活用計画が必要 | 高 |
| **ISO/IEC 27001** | 全社 | 認証取得済み（オンプレミス対象） | クラウド環境への適用範囲拡大が未完了 | 高 |
| **GDPR** | EU 顧客データ処理時 | 基本対応のみ | データ処理記録・削除権対応・DPA 締結が不完全 | 高（EU 展開時） |
| **PCI DSS v4.0** | 決済機能保有システム | v3.2.1 対応済み | v4.0 への移行計画が未策定、クラウド環境での SAQ 更新が必要 | 高 |
| **SOC 2 Type II** | 顧客向け SaaS サービス | 未取得 | 信頼サービス基準への対応とレポート取得が必要 | 中 |
| **NIST Cybersecurity Framework** | インフラ全般 | 部分参照 | フレームワーク全体の適用とギャップ分析が未実施 | 中 |

### 3.3 リスク管理体制

#### クラウド導入に伴う主要リスクと対応策

| リスクカテゴリ | リスク内容 | 発生確率 | 影響度 | リスクスコア | 推奨対応策 |
|---|---|---|---|---|---|
| **財務リスク** | クラウドコストの予期しない増加（スプロール） | 高 | 中 | 高 | Azure Budget アラート、タグ管理ポリシー、FinOps 実践 |
| **セキュリティリスク** | 設定ミスによるデータ漏洩 | 中 | 最高 | 高 | Microsoft Defender for Cloud、Azure Policy、IaC 標準化 |
| **コンプライアンスリスク** | 個人情報の不適切なクラウド保存 | 中 | 高 | 高 | データ分類・ラベリング、Microsoft Purview 活用 |
| **運用リスク** | クラウドスキル不足による設定ミス | 高 | 高 | 高 | トレーニング計画、CCoE 設立、ピアレビュープロセス |
| **ベンダーロックインリスク** | 特定クラウドへの過度な依存 | 低 | 中 | 中 | マルチクラウド戦略の検討、標準 API・コンテナ技術の活用 |
| **可用性リスク** | クラウドサービス障害による業務停止 | 低 | 高 | 中 | マルチリージョン設計、DR 計画策定 |
| **移行リスク** | データ移行中のデータ消失・破損 | 低 | 高 | 中 | バックアップ強化、段階的移行、ロールバック計画 |

### 3.4 コスト管理の現状

#### 現行のコスト管理課題

| 課題 | 詳細 | クラウド移行後の解決策 |
|---|---|---|
| コスト配賦の不透明性 | IT コストが部門別に配賦されておらず、各部門のシステム利用コストが不明確 | Azure タグ付けポリシー + Azure Cost Management でリソース単位・部門別コストを可視化 |
| 予算超過の事後検知 | コスト超過をリアルタイムに検知できず、四半期末に発覚するケースが多い | Azure Budget アラートとコスト異常検知（Anomaly Detection）でリアルタイム検知 |
| FinOps 文化の未醸成 | エンジニアチームがコストを意識した設計・運用を行っていない | FinOps Foundation の原則に基づくクラウド会計モデルの導入、チャージバック/ショーバック制度の確立 |
| ライセンス最適化の未実施 | オンプレミスのソフトウェアライセンスを Azure Hybrid Benefit で再活用できていない | Azure Hybrid Benefit 適用によるライセンスコスト削減（推計 40%） |

2. **SQL Server 2012**: 8 インスタンスがサポート終了済み
3. **レガシーアプリケーション（COBOL 基幹システム）**: COBOL ベースの基幹システムが 3 本存在
   - **勘定系 COBOL（業務A）**: 約 30 万行、Azure への直接移行不可 → **Retain（2 年）→ Rebuild 検討**
   - **在庫管理 COBOL（業務B）**: 約 15 万行、外部ベンダー依存 → **Retain（2 年）→ Replace（SaaS）検討**
   - **人事給与 COBOL（業務C）**: 約 10 万行、年次更新頻度低 → **Retain（3 年）→ Replace（SaaS）検討**
   > ⚠️ COBOL 3 本の対応が完了するまで DC の完全廃止は不可能です。DC 契約延長コストを TCO に織り込んでください。
4. **モノリシックアーキテクチャ**: 主要 Web アプリの 60% がモノリシック構成でスケーラビリティに限界

> DC 契約の 1 年延長オプションの確認を最優先事項として実施してください。
> COBOL 基幹システム 3 本が残存する間は DC の完全廃止は不可能です。

## 8. 推奨事項

### 8.1 即時対応事項（0〜3 ヶ月）

#### 🔴 セキュリティ緊急対応

**S-01: 平文シークレットの Azure Key Vault への移行（〜1 ヶ月）**
- 対象: アプリケーション設定ファイルに保存されているパスワード・API キー・接続文字列
- 対応: Azure Key Vault を作成し、アプリケーションはマネージド ID 経由でシークレットを取得する設計に変更
- 担当依頼先: @cloud-security（実装計画）、@cloud-platform（Key Vault 構築）
- 期待効果: 情報漏洩リスクの即時低減

**S-02: 多要素認証（MFA）の全社展開（〜2 ヶ月）**
- 対象: 全従業員・全管理者アカウント
- 対応: Microsoft Authenticator アプリを標準認証手段として展開。Microsoft Entra ID の条件付きアクセスポリシーで MFA を強制
- 担当依頼先: @cloud-security（ポリシー設計）
- 期待効果: フィッシング・パスワードリスト攻撃への耐性向上（推計 99.9% の自動攻撃を防御）

#### 🔴 プラットフォーム基盤構築

**P-01: Azure Landing Zone の設計・構築（〜3 ヶ月）**
- 内容: Management Group 階層設計、Hub VNet 構築、基本 Azure Policy 適用、Log Analytics Workspace 構築
- 担当依頼先: @cloud-platform（設計・実装）、@cloud-governance（ポリシー定義）
- 成果物: 本番環境対応の Landing Zone（Bicep テンプレートで再現可能な状態）

**P-02: 先行移行ワークロード（Quick Wins）の選定と移行（〜3 ヶ月）**
- 対象: 開発・テスト環境、社内ファイルサーバー（OneDrive 移行）、バックアップ基盤（Azure Backup）
- 期待効果: チームのクラウドスキル向上、早期コスト削減（推計月次 ¥500〜800 万削減）

#### 🔴 ガバナンス・組織

**G-01: FinOps 体制の初期整備（〜2 ヶ月）**
- 内容: Azure Cost Management の設定、リソースタグ付けポリシーの策定、Budget アラートの設定
- 担当依頼先: @cloud-governance（ポリシー実装）
- 期待効果: クラウドコストの可視化とスプロール防止

**O-01: CCoE（Cloud Center of Excellence）設立準備（〜3 ヶ月）**
- 内容: CCoE チームメンバーの選定、チャーターの作成、初期ミーティングの開始
- 期待効果: クラウド戦略の組織的推進力の確立、各チームの連携強化
